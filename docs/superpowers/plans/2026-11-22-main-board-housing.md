# Main Board Housing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A two-part ASA housing (base + lid), IP67 by design, for the plan4 main board, modelled in Fusion
from dimensions read out of `hardware/mccan.kicad_pcb`, with clearance checks and print/mould exports.

**Architecture:** Three stages, each a file in `hardware/enclosure/`.
1. `extract_board.py` reads the board file and writes `board.json`.
2. `layout.py` turns `board.json` and a parameter table into every housing coordinate (`layout.json`),
   and asserts the design rules in plain Python.
3. `build_housing.py`, a Fusion API script, draws `layout.json` in a new Fusion document and runs the
   interference check.

Fusion only draws. Every number is decided, and checked, in testable stdlib Python.

**Tech Stack:** Python 3.14 stdlib (no new packages); Fusion API (Fusion's embedded Python) through
the Fusion MCP `script` tool; `kicad-cli` 10.0 for the board STEP.

**Spec:** `docs/superpowers/specs/2026-11-22-main-board-housing-design.md`

## Global Constraints

- Never edit `hardware/mccan.kicad_pcb`, `hardware/sheets/`, `hardware/output/` or `hardware/scripts/`.
- Housing coordinates are **board coordinates**: KiCad (x − 20, y − 20). +x runs right, +y runs toward
  the cable edge, and z = 0 is the inside floor.
- The no-metal antenna zone is x 55.75–134.25, y −15 to 21.44, at every z.
- Nominal wall 2.5 mm. Draft 1° on vertical faces. No undercuts.
- Standoffs ≥ 5 mm (use 8). Standoff top face Ø6.0 mm. L2 top to lid underside ≥ 3 mm (target 4).
- Lid screws: M3 into brass heat-set inserts, outside the gasket groove, pitch ≤ 60 mm except along
  the antenna wall.
- Gasket: Ø2.0 mm silicone cord; groove about 1.5 deep × 2.7 wide.
- Glands, left to right: feedA M12, front M12, rear M12, CAN M12, podL M16, feedB M16, podR M16. Two
  staggered rows on the cable wall (+y).
- Part numbers that have not been looked up are written **[TO CONFIRM]**, never invented.
- Tests are plain scripts: `python <test>.py`, which exits 1 on failure (repo convention).
- Commit or push only when the owner asks in the session. The commit steps below are held until then.
- Don't save the owner's other open Fusion documents, and don't modify them.

## Review Focus

1. **The antenna zone breached by derived geometry.** A screw, insert or ear sleeve that the screw
   pitch rule or a resized flange pushes into x 55.75–134.25 must fail `layout.py`'s check, not pass
   silently. (Task 2 test `test_antenna_zone_rejects_screw`.)
2. **Glands that don't fit at the chosen height.** If the hexes of two staggered glands overlap, or
   the upper row hits the flange, the layout must raise an error rather than draw overlapping holes.
   (Task 2 `test_gland_overlap_detected`.)
3. **A part whose 3D model is missing, read as height 0.** The extractor must take its height from
   the fallback table or fail. It must never default to 0. (Task 1 `test_every_part_has_height`.)
4. **A rotated footprint's courtyard.** Courtyards of footprints at 90°, 180° or 270° must be rotated
   into board coordinates. (Task 1 `test_rotated_courtyard`, using C6 at 90°.)
5. **Lid clearance when the interior height is derived.** Changing the standoff height must move the
   lid. (Task 2 `test_lid_clearance_tracks_standoff`.)

### Task 1: Board extractor → `board.json`

**Files:**
- Create: `hardware/enclosure/extract_board.py`, `hardware/enclosure/test_extract_board.py`
- Output: `hardware/enclosure/board.json` (committed, regenerated by the script)

**Interfaces:**
- Produces: `load(pcb_path) -> dict` and a CLI that writes `board.json`. The dict has these keys:
  - `outline`: `{w, h, r, t}`
  - `holes`: `[{ref, x, y, d}]`
  - `parts`: `[{ref, x, y, rot, bbox:[x0,y0,x1,y1], height, height_src}]`, where `bbox` is the F.CrtYd
    courtyard (or the pad extent if there is no courtyard), in board coordinates
  - `tails`: `[{ref, pads:[[x,y,d]]}]`
  - `access`: `{J2:[x0,y0,x1,y1], SW1, SW2, TP:[[x,y]]}`
  - `antenna`: `{copper:[70.75,0,119.25,6.44], zone:[55.75,-15,134.25,21.44]}`

- [ ] **Step 1: Write the failing tests** in `test_extract_board.py` (plain asserts, run on the real
      board file):
  - `outline == {w:140, h:100, r:1, t:1.6}`
  - the holes are H1 (5,5), H2 (135,5), H3 (5,95) and H4 (135,95), each with d = 3.2
  - `test_every_part_has_height`: every part has height > 0; L2's height is 24.0 with
    `height_src == "table"`
  - the tallest part is L2; C3 and C68 are each 10.5 ± 0.3
  - `test_rotated_courtyard`: C6's bbox is taller (y) than wide (x)
  - the tail refs are exactly J1, J3, J4, J5, J8, J9, J10, J11, and every tail pad has y > 75
  - `antenna.zone == [55.75, -15, 134.25, 21.44]`
- [ ] **Step 2:** Run `python hardware/enclosure/test_extract_board.py` and expect it to fail on
      `ModuleNotFoundError`.
- [ ] **Step 3: Implement `load`.**
  - Find footprints with the same s-expression regex approach as the earlier recon.
  - Rotate pad and courtyard points by the footprint's `at` angle. KiCad's angle is clockwise in
    screen coordinates: x' = x cos θ + y sin θ, y' = −x sin θ + y cos θ.
  - Heights:
    - Read each part's height from the bounding-box z of its 3D model where `kicad-cli` resolves the
      model. Simplest approach: parse the `.step` file's CARTESIAN_POINT z-range under
      `${KICAD10_3DMODEL_DIR}`.
    - Otherwise use `FALLBACK_HEIGHT`, each entry with a datasheet comment:
      - L2 24.0 (`enclosure.md` §1);
      - U1 and U2 1.75 (SOIC);
      - U14 1.2;
      - Q13 and Q14 1.1;
      - SW1 and SW2 3.8 [TO CONFIRM];
      - J tails 3.0 (solder fillet + wire bend allowance);
      - L6 2.0;
      - TPs and NT1 0.1;
      - U11–U13 1.2;
      - mounting holes 0.
    - Raise an error on any part that has neither.
- [ ] **Step 4:** Run the test and expect PASS. Run `python hardware/enclosure/extract_board.py` and
      expect `board.json` to be written.
- [ ] **Step 5: Commit** (when the owner asks): `feat(enclosure): extract board geometry for the housing`

### Task 2: Layout and rule checks → `layout.json`

**Files:**
- Create: `hardware/enclosure/layout.py`, `hardware/enclosure/test_layout.py`
- Output: `hardware/enclosure/layout.json`

**Interfaces:**
- Consumes: `board.json` (Task 1).
- Produces:
  - `P`, a dict of parameters, all in mm: `wall 2.5, draft 1.0, side_gap 3, cable_gap 22, standoff 8,
    lid_gap 4, floor 2.5, lid_t 3, flange_w 9, flange_t 4, groove_w 2.7, groove_d 1.5, cord 2.0,
    screw_d 3.0, insert_od 4.2, insert_len 5.7, max_pitch 60, ear_w 18, ear_t 3, grommet_hole 9.5,
    vent_d 12.5, glands [...]`, where each gland is `{name, ref, size:12|16, hole, hex_af, nut_af,
    nut_t}`.
    - Nylon gland AF values: M12 hex 15 / nut 15; M16 hex 19 / nut 19. These are [TO CONFIRM] and
      sit in the parameter table.
  - `build(board, P) -> dict` returns:
    - `interior {x0, y0, x1, y1, h}`
    - `bosses [{x, y, top_d}]`
    - `screws [{x, y}]`
    - `glands [{name, x, z, size}]`
    - `vent {wall, y, z}`
    - `ears [{x, y}]`
    - `groove`: centre-line rectangle and corner radius
    - `lid {z_underside}`
  - `check(board, layout, P) -> list[str]` returns violations; empty means pass.
  - The CLI writes `layout.json` and exits 1 if `check` returns anything.

- [ ] **Step 1: Write the failing tests** in `test_layout.py`:
  - `test_default_passes`: `check(...) == []`
  - `test_interior`: interior is 146 × 125, with x0 = −3, y0 = −3, x1 = 143, y1 = 122
  - `test_lid_clearance_tracks_standoff`:
    - with standoff 8, `lid.z_underside − (8 + 1.6 + 24.0) ≥ 3`;
    - with `standoff = 12`, `lid.z_underside` grows by 4.
  - `test_antenna_zone_rejects_screw`: append a screw at (90, −8) to the layout, and `check` reports
    "antenna".
  - No default screw, insert or ear lies within the zone.
  - Screw pitch:
    - adjacent screws ≤ 60 mm apart, except the pair spanning the antenna wall;
    - every screw lies outside the groove by ≥ insert_od/2 + 1.
  - `test_gland_overlap_detected`: with `cable_gap` default and the gland `hex_af` raised to 30,
    `check` reports "gland".
  - Default glands:
    - every pair's hexes are ≥ 2 mm apart (centre distance ≥ (af₁ + af₂)/2·1.155 + 2);
    - each nut is ≥ 1 mm above the floor (z = 0) and ≥ 1 mm below the flange underside;
    - x is within the interior.
  - Bosses:
    - top_d is 6.0;
    - the boss's draft-widened base (radius at z = 0) misses every courtyard bbox by ≥ 0.5 mm. This is
      checked against the bboxes in `board.json`, because the boss is under the board and only its
      top touches it. The real constraint is underside protrusions near the hole: assert no tail pad
      is within boss radius + 1.
- [ ] **Step 2:** Run `python hardware/enclosure/test_layout.py` and expect FAIL.
- [ ] **Step 3: Implement `build` and `check`.**
  - Screws:
    - Place them on the flange centre line. Start at the four corners, then insert evenly spaced
      screws per side until the pitch is ≤ max_pitch.
    - On the antenna (y = min) side, delete any screw inside the zone and re-space the remainder
      left of the zone.
  - Glands:
    - Each gland centre x is the mean x of its tail's pads, clamped to the interior.
    - Alternate the rows low, high, low… across the seven glands.
    - Low z = nut_af·0.577 + 1.5; high z = flange underside − nut_af·0.577 − 1.5.
    - If a pair still conflicts, shift x apart symmetrically. Raise an error only if the shift leaves
      the interior.
  - Vent: on the +x wall, y = interior.y1 − 15, z = 10.
  - Ears: on the ±x walls, at y = interior.y0 + 20 and interior.y1 − 20.
- [ ] **Step 4:** Run the tests and expect PASS. Run `python hardware/enclosure/layout.py` to write
      `layout.json` and exit 0.
- [ ] **Step 5: Commit** (when the owner asks): `feat(enclosure): parametric layout and rule checks`

### Task 3: Fusion model

**Files:**
- Create: `hardware/enclosure/build_housing.py`, a Fusion script whose entry point is `run(_context)`.
  It reads `layout.json` from an absolute path in a `LAYOUT` constant at the top.

**Interfaces:**
- Consumes: `layout.json` (Task 2).
- Produces: a new Fusion document "ESP32MCCAN Housing" with these components:
  - `Base`
  - `Lid`
  - `Gasket` (the cord, a swept circle)
  - `Hardware` (inserts and screws as plain cylinders)
  - `Glands` (thread cylinder plus outside hex plus inside nut)
  - Every `P` value is also a Fusion user parameter, for the owner's manual edits.

- [ ] **Step 1: Build the base.**
  - Shell the interior box, with draft.
  - Flange, with the groove cut into the flange face.
  - Insert holes (the insert's hole diameter, depth = insert_len + 0.5).
  - Four bosses, with draft.
  - Gland holes, each with an outside spot face (Ø hex_af + 4, 0.5 mm deep, perpendicular).
  - Vent hole.
  - Ears with grommet holes.
- [ ] **Step 2: Build the lid.**
  - A plate with outline equal to the flange's, thickness lid_t.
  - A locating skirt 0.3 mm inside the wall.
  - Screw clearance holes Ø3.4.
  - Stiffening ribs on the underside, 1.5 mm, along the antenna wall and across. The ribs keep
    lid_gap ≥ 3 over L2's footprint.
- [ ] **Step 3: Verify.**
  - Run it through the MCP `script` tool. Expect "built" printed with the body count and each body's
    volume, and no error.
  - Take a screenshot (iso-top-right) and confirm by eye: the glands sit on the +y wall and the
    flange screws avoid the antenna span.
- [ ] **Step 4: Commit** (when the owner asks): `feat(enclosure): Fusion build script`
